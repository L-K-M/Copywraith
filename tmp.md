# Copywraith review, 2026-09-25 (`tmp.md`)

Fresh, code-first review of `main` at `a4dc499` (0.3.1). Scope: shared core,
server, admin UI, Tauri desktop/mobile backend, popup UI, Linux layer, Android
plugin, CI and deployment.

This is a working document. It deliberately concentrates on findings that are
**not already in `ANALYSIS.md`**, or that add a new mechanism or evidence to an
entry that is. Where an item overlaps with `ANALYSIS.md`, the overlap is named
so the two can be merged without duplication. Maintainer positions recorded in
`ANALYSIS.md` are respected: the System 7 look, varied type sizes, mixed accents
and no dark mode are intentional; single-click-to-paste is a product decision;
`synchronous=FULL` stays; star reconciliation stays keyed on `content_hash`.

Severity is impact, not effort. Every "Evidence" line was checked against the
code; claims that were measured are marked **(verified)**.

## 1. Top findings

The things most worth fixing, in order.

1. **AND-N1: any Android app can make Copywraith import its own database** (with
   the plaintext server password) through a `file://` share and sync it to every
   device.
2. **SEC-N1: password-manager copies are captured and synced.** Nothing honours
   the "concealed/transient" clipboard markers that 1Password, Bitwarden,
   KeePassXC and KeePass set, so every copied password is stored in plaintext
   SQLite on each device and uploaded to the server.
3. **ADM-N1: a password with a non-ASCII character or trailing space is accepted
   at setup and then locks every client out**, with no recovery short of deleting
   `auth.json`.
4. **AND-N2: the Shizuku listener cannot work on Android 10+** (wrong calling
   package) and on Android 11/12 bounces a `SecurityException` into whichever app
   copied.
5. **SYNC-N1: steady-state polling downloads the newest 100 full entries every
   5 seconds per client**, even when nothing changed.
6. **SYNC-N2: a wrong password, a 500, or a locked server shows as a green
   "online / last sync completed successfully".**
7. **SYNC-N3: the 30 s whole-request HTTP timeout turns any large blob on a slow
   link into a permanent retry loop** (push re-encodes it every 5 s; pull pins
   the watermark forever).
8. **SYNC-N4: changing the server URL keeps the old server's watermark**, so the
   new server's older entries are never pulled.
9. **UX-N1: starring blocks on the network** for up to ~20 s when a server is
   unreachable, because `toggle_star` awaits the push.
10. **SRV-N1: server startup reads (and after each restart, rewrites) the entire
   entries table.**
11. **CAP-N1: copying several files where one is an image stores only that
   image**; the other files are silently dropped.
12. **SYNC-N5: re-copying something never reaches the server or other devices**,
   and starring conversely *does* reorder history everywhere.
13. **SEC-N2: no Content-Security-Policy, and `get_settings` hands the server
    master password to the WebView.**

## 2. Security and privacy

### SEC-N1 (High): concealed/transient clipboard content is captured and synced

- **Evidence:** `src-tauri/src/native_clipboard.rs:64-113` reads Image, Files,
  Text/HTML/RTF and nothing else. `grep -ri 'concealed\|transient\|passwordManagerHint'`
  over the repo finds nothing in code.
- **Mechanism:** password managers mark their clipboard writes so that
  clipboard managers skip them:
  - macOS (nspasteboard.org convention): `org.nspasteboard.ConcealedType`,
    `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`,
    plus legacy `com.agilebits.onepassword`, `de.petermaurer.TransientPasteboardType`,
    `net.antelle.keeweb`, `Pasteboard generator type`.
  - Windows: `ExcludeClipboardContentFromMonitorProcessing`,
    `Clipboard Viewer Ignore`, and `CanIncludeInClipboardHistory` = 0.
  - Linux/KDE: `x-kde-passwordManagerHint` (KeePassXC, KWallet).
  Copywraith ignores all of them. `sensitive.rs` only catches structured
  secrets (API-key prefixes, `password=`), so an ordinary generated password
  such as `correct-horse-battery` is stored unmasked, pushed with the master
  password as bearer token over (typically) plain HTTP, and kept forever
  because nothing expires entries.
- **Fix:** check `ClipboardContext::has(ContentFormat::Other(..))` for the
  markers at the top of `NativeClipboard::read` and return a new
  `ClipboardPayload::Concealed` that capture drops. `clipboard-rs` supports
  custom formats on every desktop backend, and the existing
  `server/tests/native_clipboard.rs` already runs on Linux/macOS/Windows CI,
  so this can be tested end to end. Follow-up: a Settings toggle for
  `TransientType`/`AutoGeneratedType` (some users want those).
- **Relation:** new. `ANALYSIS.md` "Local privacy" asks for per-app exclusion;
  this is the standard, zero-configuration half of that.

**Follow-up from PR #147 review:** Windows `CanUploadToCloudClipboard` = 0
means "local history allowed, no cloud upload". Honouring it properly needs a
local-only entry flag (capture, never push), not a skip; the privacy-marker PR
only skips content that forbids recording outright.

### SEC-N2 (Medium): no CSP, and the master password is readable from the WebView

- **Evidence:** `src-tauri/tauri.conf.json` has `"security": {}` (no `csp`).
  `commands::get_settings` returns `Settings` including `api_key`, which is the
  server master password (`SettingsDialog.svelte:41`).
- **Mechanism:** the popup renders untrusted clipboard content. Today Svelte
  escapes it, so there is no known XSS. But the roadmap wants rich HTML preview
  ("Ectoplasm tabs"); the first `{@html}` without a sandbox would give any copied
  web page script access to Tauri IPC, which exposes paste simulation and the
  master password that decrypts the whole server.
- **Fix:** add a strict CSP (`default-src 'self'; img-src 'self' data: blob:;
  style-src 'self' 'unsafe-inline'; connect-src ipc: http://ipc.localhost`),
  stop returning the password (return `has_api_key: bool`; accept an optional
  new value on save), and render any future rich preview in a sandboxed
  `iframe srcdoc` without `allow-scripts`. Needs a runtime check on each
  platform because a wrong CSP blanks the window.

### SEC-N3 (Low): unused IPC permissions

- **Evidence:** `src-tauri/capabilities/default.json` grants
  `global-shortcut:allow-register/unregister/unregister-all/is-registered`, but
  the frontend never imports `@tauri-apps/plugin-global-shortcut` (shortcuts are
  registered in Rust). The npm dependency is also unused.
- **Fix:** drop the four permissions and the npm package (least privilege: a
  compromised WebView could otherwise rebind or unbind system-wide shortcuts).

### SEC-N4 (Low): an absolute `blob_url` sends the bearer password to any host

- **Evidence:** `src-tauri/src/sync.rs:823` `resolve_url` passes absolute
  `http(s)://` URLs through; `fetch_blob_data` then attaches
  `Authorization: Bearer <master password>`.
- **Mechanism:** a malicious or misconfigured server (or anything answering on a
  mistyped fallback URL) can return `blob_url: "http://elsewhere/..."` and
  harvest the password.
- **Fix:** accept only relative blob URLs (or same-origin absolute ones).

### SEC-N5 (Low): sensitive-detection false positives cannot be overridden

- **Evidence:** `sensitive.rs:112-121` flags any `token|secret|password\s*[:=]\s*\S+`,
  so a code snippet like `let token = parse(input);` is masked in the list and
  in the preview (`commands.rs:146-155` masks `get_entry_text` too). There is no
  per-entry "not sensitive" toggle and no reveal.
- **Fix:** add "Reveal" (press-and-hold) in the preview and a "Not sensitive"
  action that clears the flag locally.

## 3. Sync correctness and speed

### SYNC-N1 (High, performance): every 5 s poll downloads 100 full entries

- **Evidence:** `lib.rs:861-911` polls every 5 s. `sync.rs:278-395` always
  requests `limit=100` for the first page and only stops when it meets the
  watermark *client side*. The server (`api.rs:402`, `storage.rs:541`) decrypts
  all 100 rows (four text fields each) and runs `COUNT(*)` for every request,
  and the response carries every flavor in full (SYNC-A5).
- **Mechanism:** with no new entries, each client still transfers the newest 100
  entries, including full HTML/RTF, every 5 seconds. One rich-text copy near the
  top of history (50-500 KB) makes that megabytes per poll, per device, forever,
  over the VPN and on mobile data. The server burns 400 AES-GCM decrypts per poll
  per client.
- **Fix (client only, backward compatible):** when initialised, probe with
  `limit=1`. If the newest entry is at or below the watermark, stop: one entry
  transferred instead of 100. If not, continue with normal 100-entry pages from
  that cursor. Combine with gzip (`ANALYSIS.md` already recommends
  `CompressionLayer`; reqwest needs its `gzip` feature too) and with running the
  first pass immediately (SYNC-A7). A later protocol step is an
  `updated_after` cursor so the walk runs forward and each page commits the
  watermark (this also fixes SYNC-A3).
- **Relation:** extends SYNC-A5/A6/A7. The steady-state cost itself was not
  recorded.

### SYNC-N2 (High, UX): HTTP errors and wrong passwords report "online"

- **Evidence:** `sync.rs:541-574` calls `note_responding_endpoint` *before*
  checking the status code, then skips the non-2xx response. When every endpoint
  answers non-2xx, `pull_new_entries` (`sync.rs:316-330`) falls back to
  `recent_responding_status()`, which returns `SyncEndpointStatus::online` with
  the message "Last sync check completed successfully." The frontend knows only
  `checking | disabled | online | unreachable` (`syncStatusStore.ts:3`).
- **Mechanism:** after a password change on the server, a mistyped password, a
  server that answers 403 "setup required", or a 500, the status bar stays green
  and says the last sync succeeded, while nothing uploads or downloads. The push
  side (`push_entry_with_fallback`) logs a warning and retries every 5 s forever.
- **Fix:** classify responses: 401 → `unauthorized` ("The server rejected the
  password"), 403 setup-required → `needs_setup`, other non-2xx → `error` with
  the status. Only a 2xx may produce `online`. Add the new states to the store,
  the status bar (distinct colour and text) and Sync Details.
- **Relation:** new. Complements "persistent stale/error/Retry state" in
  `ANALYSIS.md`, which assumes errors are at least reported.

### SYNC-N3 (High): the 30 s total timeout makes large blobs unsyncable

- **Evidence:** `sync.rs:146-150` builds the client with
  `.timeout(Duration::from_secs(30))`, a whole-request deadline that includes the
  body. Push sends the blob inline as base64 (`sync.rs:243-251`); pull downloads
  it in `fetch_blob_data`.
- **Mechanism:** a 20 MB screenshot is ~27 MB of base64. On a 5 Mbit/s VPN
  uplink that takes ~43 s, so the push always times out, is retried every 5 s
  (re-reading and re-encoding the blob each time), and never succeeds. On pull,
  the timeout is an `Err`, which sets `had_ingest_error`, which blocks the
  watermark, so *every later pass* re-walks and re-downloads from the top.
- **Fix:** replace the total timeout with `read_timeout` (per-read inactivity)
  plus a connect timeout, or scale the deadline with payload size. Add
  per-entry failure counts with backoff so one bad row cannot monopolise the
  loop.
- **Relation:** new mechanism; `ANALYSIS.md` "Bound and stream large payloads"
  covers the size limits, not the timeout.

### SYNC-N4 (Medium): switching servers keeps the old watermark

- **Evidence:** `commands::update_settings` (`commands.rs:944-950`) only saves.
  Neither it nor `SettingsDialog.handleSave` resets the pull cursor; only the
  mobile-only "Reset Sync Cursor" button does (`SettingsDialog.svelte:161`).
- **Mechanism:** the watermark is an `(updated_at, id)` from the *old* server.
  After pointing the client at a different server (or at a rebuilt one), every
  entry on the new server older than that timestamp sorts below the watermark
  and is never pulled. Desktop has no reset button at all.
- **Fix:** reset the cursor when either URL changes (ingestion is idempotent, so
  the cost is one metadata re-walk). Better, in a follow-up: have `/api/health`
  return a random per-database `server_id` and key the watermark to it, which
  also catches a wiped server behind an unchanged URL.

### SYNC-N5 (Medium): recency does not sync; starring reorders everything

- **Evidence:** a duplicate capture takes `insert_entry`'s early return
  (`storage.rs:248-255`): it bumps local `updated_at` but leaves `synced = 1`,
  and `clipboard.rs:178-181` only emits `clipboard-reordered`. On pull,
  `ingest_remote_entry` (`sync.rs:622-625`) applies only the star state to a
  known hash. Conversely `toggle_star` (client `storage.rs:500-514`, server
  `storage.rs:705-713`) sets `updated_at = now`.
- **Mechanism:** copy "foo" on Monday and again on Wednesday on the Mac: the Mac
  shows it on top, the server and phone still show Monday. Starring an entry
  from last month, by contrast, moves it to the top of history on every device.
  `updated_at` is doing two jobs: "last used" (sort order) and "last modified"
  (sync version).
- **Fix:** split the two. Add a `revision`/`modified_at` used only as the sync
  cursor, and keep `updated_at` (or a new `last_used_at`) for ordering. Then a
  recopy bumps both and is pushed; a star bumps only the revision.
  `apply_remote_star_state_by_content_hash` should also stop stamping local
  `now()` into `updated_at` (`storage.rs:541-545`), which makes the same entry
  carry different timestamps on different devices.
- **Relation:** related to "Separate create/recopy from star mutation" in
  `ANALYSIS.md`, which is about star clobbering; the recency loss is new.

### SYNC-N6 (Low): a remote-star apply rewrites `updated_at` with local time

Covered in SYNC-N5's fix; listed so it is not lost if SYNC-N5 is done in parts.

### SYNC-N7 (Low): pulled images without `blob_hash` are downloaded before dedup

- **Evidence:** `sync.rs:606-620`: when a remote image lacks `blob_hash` (legacy
  rows), the blob is fetched just to compute the hash, even if the entry is
  already local. Only legacy data is affected; worth a one-line comment or a
  server-side backfill of `blob_hash`.

## 4. Server

### SRV-N1 (Medium, performance): startup scans and rewrites the whole table

- **Evidence:** `server/src/storage.rs:75-141` (`backfill_flavor_columns`)
  selects every row into a `Vec`, runs `merge_legacy` and `best_plain_text`
  (full HTML/RTF stripping) on each, and updates rows that differ. It runs on
  every start, unguarded. The client has the opposite, explicit rule
  (`src-tauri/src/storage.rs:123-126`: "avoid loading and rewriting the entire
  history table on every launch").
- **Mechanism:** with encryption active (mandatory now), text fields are
  independent ciphertexts, so `text_content != to_legacy_text_content()` and
  `search_text != best_plain_text()` for every text row created since the last
  start. Each restart therefore rewrites every new row once, and always reads the
  whole table into memory first. On a NAS-class box with a large history this is
  slow startup and a memory spike proportional to total text size.
- **Fix:** record a `flavor_backfill_version` in the existing `metadata` table
  (the FTS schema already does exactly this) and skip the pass once done.

### SRV-N2 (Low): FTS5 is dead code under mandatory encryption, with a latent 500

- **Evidence:** every data endpoint calls `ensure_authorized`, which requires a
  configured password (`api.rs:723-740`), so a DEK is always present and
  `list_entries` always takes the in-memory decrypt-and-scan path
  (`storage.rs:559-563`). The FTS triggers skip `ENC:1:` rows, so `entries_fts`
  stays empty. If the plaintext path is ever reached (e.g. the lock/DEK race),
  the raw search string goes straight into `MATCH`: **(verified)** with SQLite
  3.45, `user@example.com`, `https://x`, `a-b`, `e-mail`, `AND` and a lone `"`
  all raise errors, which surface as HTTP 500.
- **Fix:** decide. Either drop FTS (and the doc claims in `ARCHITECTURE.md`), or
  keep it for an explicit "unencrypted server" mode and quote the term as an FTS5
  phrase (`"..."` with doubled quotes). Search over encrypted data needs a
  different design (client-side search, or a blind index), which is the real
  fix for the full-table decrypt already listed as SYNC-A6.

### SRV-N3 (Low): blob responses are not cacheable

- **Evidence:** `api.rs:602-646` returns blobs with only `Content-Type`.
- **Fix:** blobs are content-addressed and immutable, so add
  `Cache-Control: private, max-age=31536000, immutable` and an `ETag` of the
  hash. The admin UI then stops re-downloading thumbnails.

### SRV-N4 (Low): `health` takes the crypto lock and runs `COUNT(*)`

Minor: fine at current scale, but `/api/health` is a natural liveness probe and
should not contend with the global mutex (see "Server scalability" in
`ANALYSIS.md`).

## 5. Desktop capture and paste

### CAP-N1 (Medium): multi-file copies collapse to one image

- **Evidence:** `clipboard.rs:77-91`: for any file list, `read_first_image_file`
  returns the first image among the files and the whole copy is stored as that
  image.
- **Mechanism:** select `report.pdf` and `photo.png` in Finder and copy: history
  gets one image entry, and pasting it gives the image, not the two files.
- **Fix:** only convert when exactly one file was copied and it is an image;
  otherwise keep the file list.

### CAP-N2 (Medium): `file://` URIs are not percent-decoded

- **Evidence:** `native_clipboard.rs:81` strips the `file://` prefix but leaves
  `%20` etc., so `my file.png` is stored as `my%20file.png`: the image read in
  CAP-N1 fails and the file list shows escaped names.
- **Relation:** listed in `ANALYSIS.md` as "pre-existing URI escaping" follow-up
  without a mechanism; this is it. Fix with a small percent-decoder.

### CAP-N3 (Medium, verify on device): image flavor beats text

- **Evidence:** `native_clipboard.rs:69-74` returns `Image` whenever the
  clipboard advertises an image.
- **Mechanism:** Microsoft Office, LibreOffice Calc and some browsers put a
  rendered picture *next to* the text when you copy text or cells. Copywraith
  then stores a picture of the spreadsheet cells instead of the text. Worth
  confirming on macOS/Windows before changing.
- **Fix:** if non-empty `text/plain` is present and the HTML is not just a lone
  `<img>`, store the text flavors (ideally keep the image as an extra flavor).

### CAP-N4 (Low): no size cap on clipboard images

- **Evidence:** file images are capped at 32 MiB (`clipboard.rs:193`) and
  Android shares at 64 MiB, but `ClipboardPayload::Image` is unbounded; a
  screenshot of a large display re-encoded to PNG can exceed the server's
  64 MiB body limit after base64, and then retries forever (SYNC-N3).

### CAP-N5 (Low): "paste as plain text" trims the text

- **Evidence:** `paste_entry_plaintext` and `paste_most_recent_plaintext` use
  `best_plain_text()`, which trims (`models.rs:125-127`).
- **Mechanism:** copy an indented code line `    return x;`, paste as plain
  text, and the indentation (and any trailing newline) is gone. Plain paste
  should change formatting, not content.
- **Fix:** prefer the untrimmed `text_plain` when present; fall back to the
  stripped HTML/RTF.

### CAP-N6 (Low): the paste-plaintext shortcut fires on key *press*

- **Evidence:** `lib.rs:315` uses `ShortcutState::Pressed` for the plaintext
  shortcut, while the popup shortcuts use `Released`. With `Cmd+Shift+Alt+V`
  still held, the synthetic `Cmd+V` can arrive with Shift/Alt physically down,
  which many macOS apps interpret as "Paste and Match Style" or nothing.
  Needs a device check; consider firing on release, or waiting for modifiers to
  lift.

### CAP-N7 (Low): source-app cache polls with `osascript` fallback

- **Evidence:** `paste.rs:23-44` polls every second forever;
  `detect_frontmost_app_name` falls back to spawning `osascript` whenever the
  native lookup returns `None`, which it does whenever Copywraith itself is
  frontmost. `ANALYSIS.md` already recommends workspace activation
  notifications; this adds the cost (a process spawn per second while the popup
  is focused).

## 6. Popup UI and UX

### UX-N1 (Medium): starring waits for the network

- **Evidence:** `commands::toggle_star` (`commands.rs:183-191`) awaits
  `sync_entry`, i.e. an HTTP push with a 10 s connect timeout per endpoint.
  `clipboardStore.toggleStar` updates the row only after the invoke resolves.
- **Mechanism:** with the server unreachable (VPN down, laptop off-LAN), clicking
  the star does nothing visible for up to ~20 s. On a working server it still
  waits one round trip.
- **Fix:** update locally, return immediately, and push in the background like
  capture does (`clipboard.rs:172-176`).

### UX-N2 (Medium): keyboard coverage is thin for a keyboard-summoned tool

- **Evidence:** `+page.svelte:417-471` and `FilterBar.svelte:46-72` handle only
  arrows, Enter, Escape and `Cmd+,`.
- **Missing:** `Cmd+1..9` quick paste (in `ANALYSIS.md`), `Shift+Enter` paste as
  plain text (Opt+click has no keyboard equivalent), `Cmd+Backspace`/`Delete`
  delete, `Cmd+S` star, `Cmd+P`/`Space` preview from the filter field,
  `PageUp/PageDown/Home/End`, `Cmd+F` refocus filter.
- **Fix:** add them in one handler shared by the filter field and the list, and
  show them in the status-bar hint and a `?` cheat sheet.

### UX-N3 (Low): hover and selection look identical

- **Evidence:** `EntryRow.svelte:285-293` gives `:hover` and `.selected` the same
  black highlight. With the mouse resting over one row and the keyboard
  selection on another, two rows look selected, and Enter pastes the one the
  user may not expect.
- **Fix:** keep full inversion for the selection only; use a System 7 style
  dotted outline or 50% grey pattern for hover.

### UX-N4 (Low): shortcut fields accept anything and fail silently

- **Evidence:** `SettingsDialog.svelte:284-317` are free-text inputs;
  `register_shortcuts` only `log::warn!`s a failed registration (`lib.rs:283`).
- **Fix:** a key-recorder field, validation before save, and surfacing
  registration failures in `shortcut_status` for the in-process mechanism too.

### UX-N5 (Low): dead error banner state

`+page.svelte:37` declares `errorMessage` and renders `ErrorBanner`, but nothing
ever sets it. Either wire persistent errors (sync unauthorized, monitor failed)
into it, or remove it.

### UX-N6 (Low): the preview shows "Created" while the list shows last use

`EntryPreview.svelte:121-123` shows `created_at`; the row shows `updated_at`
relative time. Show both ("First copied", "Last copied").

## 6b. Admin UI (`server/ui`)

Findings from a dedicated pass that ran the built server against a throwaway
data directory. Tested live where marked.

### ADM-N1 (High): non-ASCII or trailing-space passwords lock every client out

- **Evidence:** setup only checks byte length (`api.rs:172`); `extract_bearer`
  (`api.rs:756-764`) uses `HeaderValue::to_str()`, which rejects any non-visible-
  ASCII byte; hyper trims trailing whitespace; browsers throw before sending a
  header with characters above U+00FF.
- **Tested live:** `Grüezi-2026` → setup 200, unlock 200, every `/entries` 401.
  `password123 ` (trailing space) → 401. The admin UI loops between unlock and
  401 with no message; native clients cannot build the header at all (reqwest
  rejects it, which surfaces as "unreachable"). `change-password` also needs the
  header, so the only recovery is deleting `auth.json` by hand.
- **Fix:** now: reject such passwords at setup/change (printable ASCII, no
  leading/trailing whitespace) in server and UI. Later: a versioned scheme that
  sends `base64url(utf8(password))`, keeping the legacy form.

### ADM-N2 (Medium): sorted by last use, labelled "Created"

Both server queries order by `updated_at DESC` (`storage.rs:619,674`) while the
row shows `created_at` under "Created" (`App.svelte:65`, `EntryRow.svelte:113`).
Starring an entry on page 3 moves it to the top of page 1 and the list looks
unsorted. Show "Last used" (or both), and apply PATCH responses in place instead
of reloading (`App.svelte:219`).

### ADM-N3 (Medium): downloading a sensitive entry saves the mask

`get_entry` masks sensitive entries (`api.rs:497`) and `triggerDownload`
(`App.svelte:289-306`) writes whatever it received, so the user saves
`sk-•••…` believing it is the secret. Disable or label Download for sensitive
entries.

### ADM-N4 (Medium): a failed Lock looks locked but is not

`lockServer` clears the session only after `await fetch` (`api.ts:136-140`); a
network error skips that and `handleLock` swallows it (`App.svelte:141-144`).
The unlock screen shows, but the password is still in `sessionStorage`, so a
reload goes straight back in. Clear first, unconditionally, and report failure.

### ADM-N5 (Medium, latent): JSON cursors duplicate a row per page

**(verified live)** The DB stores `…+00:00` (`to_rfc3339`) while JSON returns
`…Z`; since `'+' < 'Z'`, a cursor built from a JSON timestamp returns the
boundary row again. Today's admin UI uses offsets and the native client
re-formats with `to_rfc3339()`, so nothing is broken yet, but the planned
ADMIN-10 cursor fix would walk into it. Parse and normalise `before_updated_at`
on the server.

### ADM-N6 (Low): API base discovery breaks behind a subpath

`api.ts:97-98` does `return resp.json()` without `await` inside `try`, so a
200 HTML catch-all at the root escapes the `try` and the subpath candidate is
never tried. Await, validate the shape, try the most specific candidate first.
(New evidence for ADMIN-15.)

### ADM-N7 (Low): search is not trimmed; FTS claim in docs is wrong

A search of spaces returns `total=0` with no hint (`App.svelte:153`). See
SRV-N2 for FTS being unused.

### ADM-N8 (Low): password in `sessionStorage`, no CSP

`api.ts:4,59-69` keeps the master password in `sessionStorage` (copied on tab
duplication); `ServeDir` sends no security headers (`main.rs:105`). No XSS was
found today (`{@html}` only in the library's `BalloonHelp` with static strings;
images via `blob:` URLs). Keep the password in memory and add
`Content-Security-Policy: default-src 'self'; frame-ancestors 'none'`.

### ADM-N9 (Low): double delete reports a false error

`ConfirmDialog` confirms on any Enter via a window capture handler and
`pendingDeleteId` clears only after the request (`App.svelte:314-318`); a
double Enter sends a second DELETE, gets 404, and shows "Failed to delete".
Guard in-flight; treat 404 on delete as success.

### ADM-N10 (Low): accessibility gaps

`/` focuses search even with a dialog open (`App.svelte:347`); the star button's
accessible name is the glyph and it has no `aria-pressed`
(`EntryRow.svelte:76-83`); the search input has no label; page range and loading
state are not announced.

### ADM-N11 (Low): detail dialog cost

`EntryDetail.svelte:68` renders up to 10 MiB of text in one `<pre>` (the native
client caps at 500k chars); opening an image re-downloads the blob, and Download
fetches it a third time. Truncate with "show all"; reuse the row's object URL.

**Admin visual ideas (System 7, no dark mode/type scale):** a "Welcome to
Copywraith" startup box instead of bare "Loading…"; wristwatch cursor plus the
library's barber-pole `ProgressBar` for loads; Finder-style inverted selection
for the focused row; a 1-bit hatched redaction bar with padlock for masked
entries (makes ADM-N3 obvious); the classic zoom-rectangle animation from row to
detail dialog, disabled under `prefers-reduced-motion`.

## 6c. Android

Findings from a dedicated pass over `crates/copywraith-share-target`, the
Kotlin plugin and Shizuku service, and the Android paths in `src-tauri`.

### AND-N1 (High, security): share staging reads Copywraith's own private files

- **Evidence:** `CopywraithSharePlugin.kt:339-357,396-398` accepts `file://`
  URIs and opens them with `openInputStream` as Copywraith's uid.
- **Scenario:** any installed app sends an explicit `ACTION_SEND` with
  `EXTRA_STREAM=file:///data/user/0/ch.lkmc.copywraith/copywraith.db`. That
  database holds the plaintext server password (`storage.rs` settings table). It
  is imported on the next focus as a file entry and pushed to the server and
  every other device.
- **Fix:** accept only `content://`, reject Copywraith's own authorities, open
  with `openFileDescriptor` and refuse anything resolving under `dataDir`.

### AND-N2 (High): the Shizuku helper cannot read the clipboard on Android 10+

- **Evidence:** `ShizukuClipboardService.kt:36,195,237` passes
  `ch.lkmc.copywraith` as `callingPackage` while running as uid 2000/0. AOSP
  `ClipboardService.clipboardAccessAllowed` runs `checkPackage(uid,
  callingPackage)` (bypassed only for root) and checks
  `READ_CLIPBOARD_IN_BACKGROUND` by package, which `com.android.shell` holds and
  Copywraith does not.
- **Mechanism:** on API 33+ shell mode `getPrimaryClip` throws and the broadcast
  swallows it (silent listener). On API 30-32 the `SecurityException` is
  delivered back to *whichever app just copied*, via its `setPrimaryClip()`,
  and persists after Copywraith dies because the helper is a daemon. Root mode
  reads return null. `CopywraithSharePlugin.kt:72-79` then overwrites the
  helper's error with `"listening"`. Transaction codes 3/6/7 (`:297-299`) follow
  the Android 9 layout; on 7.x/8.x (minSdk is 24) 6 is **remove**Listener.
- **Fix:** pass `com.android.shell`; do a test read before `addListener` and
  fail `start()` on error; stop overwriting helper status; per-API transaction
  codes or raise minSdk for Shizuku.

### AND-N3 (Medium): the staged-clipboard event never reaches the UI

`addPluginListener` needs `register_listener`/`remove_listener` permissions,
which neither `build.rs:2-8` nor `mobile.json` grant; `+page.svelte:123-128`
hides the failure, so Shizuku captures only appear on the next focus. Meanwhile
`mobile.json` grants two permissions the WebView never uses:
`startShizukuClipboardListener` (lets a script point the privileged daemon at any
URL/key) and `readShizukuClipboard` (raw text, bypasses masking). Swap them;
when wiring the event, debounce an import+push rather than calling the full
`refreshMobileEntries`.

### AND-N4 (Medium): client cannot use compression; bundled roots only

`src-tauri/Cargo.toml:33` builds reqwest without `gzip`/`zstd`, so it never
sends `Accept-Encoding` and a server `CompressionLayer` would do nothing for
Tauri clients. `rustls-tls` trusts only the bundled webpki roots, so a LAN server
with a private CA (installed as a user CA on Android) fails, pushing users to
plain HTTP. Add compression features; use `rustls-platform-verifier` or a pinned
fingerprint setting.

### AND-N5 (Medium): staged items import shuffled with import-time timestamps

Kotlin writes `created_at` and sortable filenames (`kt:376-377`); Rust ignores
`created_at` (`commands.rs:362-367`), imports in `read_dir` order (unordered),
and stamps `Utc::now()`. Sort by filename and carry `created_at` through.

### AND-N6 (Medium): Android ignores `EXTRA_IS_SENSITIVE`

The Shizuku helper has the full `ClipData` (`kt:179-182`) and uploads directly;
neither path checks `ClipDescription.EXTRA_IS_SENSITIVE` (Android 13+). Skip or
mark such clips. Counterpart of SEC-N1.

### AND-N7 (Low, security): the sender's display name becomes a desktop path

Only the on-disk name is sanitised (`kt:346`); `file_name` keeps the raw
`DISPLAY_NAME` (`kt:362`) and becomes `file_list`; desktop paste writes
`file://{name}` (`native_clipboard.rs` `write_files`). A normal share pastes an
invalid `file://report.pdf`; a hostile name like `/Users/alice/.ssh/id_rsa`
makes a desktop paste attach the desktop's own file. Keep a sanitised basename
and never treat Android file entries as desktop paths.

### AND-N8 (Low): image type trusted from the sender's MIME

`commands.rs:685-689` trusts `image/*`, so HEIC/AVIF/SVG become Image entries
that no client can decode. Classify by bytes, fall back to File.

### AND-N9 (Low): status noise and staging leaks

`coerceToText(null)` on URI clips (`kt:182`) throws, flipping status to "error"
on every image/file copy. Batches in `pending-shares/failed/` and the files they
reference (up to 64 MiB each) are never retried or deleted.

### AND-N10: push blocks pull

If the push phase of `sync_now` times out it returns without pulling
(`commands.rs:755-776`), and the loop always pushes first (`lib.rs:876`). One
stuck upload therefore also stops downloads. Pull first or run both.

**Android ideas:** "Bind to Copywraith" in the text-selection menu
(`ACTION_PROCESS_TEXT`, also enables in-place transforms); a "Summon" Quick
Settings tile that opens a transparent activity and reads the clipboard while
focused (one-swipe capture without Shizuku); a transparent share receiver with
Direct Share targets ("Send to MacBook", "Bind as starred") and a toast "1 spirit
bound"; a "A spirit arrives from MacBook" notification via UnifiedPush/ntfy with
a Copy action; a home-screen widget of recent/starred entries with sensitive
ones blurred.

## 6d. Linux desktop, deployment and CI

### OPS-N1 (Medium, security): `.dockerignore` re-includes live server data

`.dockerignore:9,12,17,29,31` re-include whole directories (`!server/`, …),
which re-includes everything under them. Checked with Docker's own
`moby/patternmatcher`: `server/copywraith-data/auth.json`, `copywraith.db`,
`server/ui/node_modules`, `dist`, `.env`, `src-tauri/target` are **not**
excluded. `Dockerfile:20` (`COPY server/ server/`) therefore bakes the live DB,
blobs and `auth.json` into a builder layer (cached locally and on remote
builders), invalidates the release build on every DB write, and copies host
`node_modules` over the fresh `npm ci`. Allow-list files, add trailing
re-excludes, narrow the COPY.

### OPS-N2 (Medium, security): release and CI run third-party code with a write token

`release.yml:8-10` grants `contents: write` and `packages: write` workflow-wide;
the reusable `ci` job inherits it (`ci.yml` has no `permissions:`). Build jobs
run npm lifecycle scripts, cargo build scripts and Gradle with persisted
credentials. `TAURI_SIGNING_PRIVATE_KEY` is exported to `tauri-action`
(`release.yml:130-131`) though no updater is configured; the keystore password
is on the command line (`:234`) and the keystore sits in the workspace (`:228`).
Default to `contents: read`, grant per job, `persist-credentials: false`, drop
the unused key, `--ks-pass env:`, keystore in `$RUNNER_TEMP`, `gradlew --stop`.

### OPS-N3 (Medium): startup race lets two instances run

The "already running?" check is at `lib.rs:51` but the listener binds only at
`lib.rs:151`, after webview, storage, shortcut registration and tray.
`linux/mod.rs:146` deletes any existing socket before binding. On GNOME Wayland
shortcuts spawn `copywraith --toggle`, so a second press during a cold start
yields two full instances: two trays, two monitors, two sync loops on one DB,
and on KDE whichever exits first calls `setInactive`, killing shortcuts for the
other. Bind first; on "address in use" try to forward, else remove the stale
socket and retry once (or `flock` a lockfile).

### OPS-N4 (Medium): "Start at login" breaks for AppImage users

`mod.rs:223-230` writes `Exec=` from `current_exe()` unquoted; inside an AppImage
that is a temporary `/tmp/.mount_…` path (the shortcut code already uses
`$APPIMAGE` for this, `shortcuts.rs:571-576`). The tray shows it checked
because `mod.rs:203` only checks the file exists. Reuse `launch_command` and
quote per the Desktop Entry spec.

### OPS-N5 (Medium): plaintext paste fires while modifiers are held (Linux too)

KDE (`kde.rs:152`), X11 (`lib.rs:315`, `Pressed`) and GNOME custom bindings all
fire on press; injection follows a fixed 140 ms sleep (`mod.rs:39`). The target
likely receives Ctrl+Alt+Shift+V (the shortcut itself) or Ctrl+Shift+V (Paste
Special in LibreOffice). Same root as CAP-N6; fire on release where possible.

### OPS-N6 (Low/Medium): local data readable by other users

The client data dir is created with default permissions (`lib.rs:91`); nothing
sets modes. `auth.json` is created with `File::create` (`crypto.rs:444`), 0644
as root in the container, inside the tracked `./copywraith-data`. Use 0700/0600
on the client and umask 077 or a `user:` in compose.

### OPS-N7 (Low): socket fallback in `/tmp` can be squatted

Without `XDG_RUNTIME_DIR` the socket is `/tmp/copywraith-<uid>.sock`
(`mod.rs:94-101`); stale-file removal fails silently under the sticky bit, bind
failure is only logged, no peer-UID check. A pre-created listener makes every
launch forward and exit. Use a private 0700 dir, `lstat` ownership, `SO_PEERCRED`.

### OPS-N8 (Low): release gate skips the KDE and native-clipboard suites

`release.yml:16-18` calls only `ci.yml`; `kde.yml` and `clipboard.yml` have no
`workflow_call`. Nothing checks the tag is on `main`.

### OPS-N9 (Low): launching from the app menu shows nothing

A flagless launch is ignored (`lib.rs:780-795`), the `.deb` entry is
`Exec=copywraith`, the popup starts hidden. Treat a flagless forwarded launch as
"show"; add `--background` for autostart.

### OPS-N10 (Low): KDE worker polls `GetNameOwner` every 250 ms

`kde.rs:99-103,157-160`: ~4 idle wakeups/s for app and bus. Subscribe to
`NameOwnerChanged` with a slow safety poll.

### OPS-N11 (Low): `android-env-persist.sh` can break shell setup

Creating `~/.bash_profile` (`:47-48,57`) makes bash login shells stop reading
`~/.profile`; `mv` over the rc file (`:89`) replaces symlinked dotfiles.

### OPS-N12 (Low): no Dependabot for Docker base images

**Minor:** `notify-send` fallback is never waited on (zombie per use,
`mod.rs:57-64`); the notification always says "Install ydotool" even when the
daemon or `/dev/uinput` is the problem; `ci.yml` jobs and release builds have no
`timeout-minutes`.

**Checked and fine:** ydotool runs without a shell and refuses unknown versions;
GNOME keybinding quoting is correct; KDE signals are sender-checked;
`window_activity.rs`; the socket in `XDG_RUNTIME_DIR` accepts only three
commands from the same user.

## 8. Ideas: interface, aesthetics, delight

All of these fit the System 7 / spooky identity. None needs dark mode or type
scale changes.

- **The ghost sleeps (pause capture).** A status-bar toggle and tray item that
  pauses capture for 5 min / 1 h / until resumed, shown as a sleeping ghost
  "zzz" glyph with a countdown. Privacy feature with personality; pairs with
  SEC-N1. `ANALYSIS.md` lists "pause/incognito" without a design.
- **Pixel type icons.** Replace the `TXT/HTML/IMG` text badges with 16×16 1-bit
  System 7 style icons (document, globe, picture, folder), with the text label
  in the tooltip. Reads faster and looks more authentic.
- **Colour swatches.** When a text entry is a colour (`#ff8800`, `rgb()`,
  `hsl()`), show a small bordered swatch before the text. Cheap and delightful
  for designers and developers.
- **URL rows.** When an entry is a single URL, show the host in bold and the
  path dimmed; offer "Open" in the preview. No network fetch.
- **Search operators.** `is:starred`, `type:image`, `app:Safari`,
  `before:2026-09-01` parsed out of the filter text. No new UI needed; the
  backend already has the columns.
- **Type-to-filter.** Typing a printable key while the list has focus sends it to
  the filter field.
- **Drag out.** Drag an entry from the popup into another app as text, image or
  file.
- **Quick-paste numerals.** Show `1`..`9` in the first nine rows while `Cmd` is
  held (the macOS menu idiom).
- **Haunting statistics.** An "About this haunting" panel: entries captured,
  most-haunted app, busiest hour, bytes held. Uses data already stored.
- **Ectoplasm diff.** Select two text entries and show a diff; useful for
  config and code snippets.
- **Join on paste.** Multi-select rows, paste them joined by newline (the
  cheapest form of the paste stack in `ANALYSIS.md`).
- **Vanishing spirits.** Sensitive and OTP entries auto-expire locally after a
  configurable time; the row fades as it ages. Extends "OTP sense".
